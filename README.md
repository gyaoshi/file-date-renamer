# RenameTime — Windows 右键菜单「文件日期重命名」工具

把文件/文件夹一键重命名为「日期 + 原文件名」：

```
某某文件.pdf（创建于 2015-10-10）  →  20151010 某某文件.pdf
```

在资源管理器中选中一个或多个文件/文件夹，右键 → **添加日期前缀**，即可批量处理。
混合选择文件和文件夹也可以，多选时一次性全部传入处理。

## 下载

前往 **[Releases](../../releases)** 下载 `RenameTime.exe`（Windows 10/11，无需安装 Python，下载后先点一次「注册到右键菜单」即可使用）。

## ⚠️ 已知问题

### HTML 文件：右键菜单行为异常，暂不可用

对 `.html` 文件使用右键菜单时，可能弹出浏览器的「你要打开此文件吗？」安全提示，**文件没有被改名，HTML 文件目前不可用**。

| 项目 | 说明 |
|---|---|
| 现象 | 点击菜单项后浏览器弹出打开确认框，而非执行重命名 |
| 影响范围 | `.html`（`.htm` 可能同样受影响）；其他类型文件、文件夹均正常 |
| 当前定位 | 程序侧的自动化测试中，HTML 文件（含带「来自 Internet」标记的 `Zone.Identifier`）可被正常重命名；但在真实资源管理器中仍复现上述现象，**根因尚未完全定位，暂视为未解决的 bug** |
| 临时规避 | ① 打开设置里的「执行后显示结果窗口」，至少能看到是否被调用；② 关闭「直接执行」，改用预览确认模式；③ 把 HTML 拖到 `RenameTime.exe` 图标上执行 |

复现时请附上 `%APPDATA%\RenameTime\launch.log`（程序每次被调用都会记录收到的参数），反馈 issue 时一并提供，便于定位。

## 一、安装（30 秒）

1. 双击 `RenameTime.exe` 打开设置界面；
2. 切到 **「右键菜单」** 标签页，点击 **【注册到右键菜单】**；
3. 完成。之后在资源管理器里选中文件/文件夹，右键就能看到「添加日期前缀」。

> 注册只写入当前用户的注册表（`HKCU\Software\Classes`），**不需要管理员权限**；
> 卸载时点【从右键菜单移除】再删除程序文件即可。

## 二、功能选项（设置界面）

### 基本设置
| 选项 | 说明 |
|---|---|
| 日期来源 | 创建日期 / 修改日期 / 访问日期 |
| 日期格式 | 内置 8 种预设，也可直接输入 strftime 代码自定义 |
| 包含时间 | 不包含 / 时分（1430）/ 时分秒（14-30-05），可设日期与时间的连接符 |
| 分隔符 | 日期与原名之间的分隔符：空格、`_`、`-`、`.`、无 |
| 位置 | 日期加在文件名**前**（前缀）或**后**（后缀，扩展名之前） |
| 直接执行 | 右键点击后立即重命名；关闭则先弹预览窗口确认 |
| 显示结果 | 执行后弹出结果窗口（含每项明细，可一键撤销） |

### 高级选项
| 选项 | 说明 |
|---|---|
| 已有日期前缀 | **跳过**（默认，防止反复右键叠成 `20151010 20151010 某某.pdf`）/ 替换旧日期 / 仍然添加 |
| 文件名冲突 | 目标已存在时自动加序号 `(1)(2)…` 或跳过 |
| 处理范围 | 文件和文件夹 / 仅文件 / 仅文件夹 |
| 递归 | 右键文件夹时，连同内部所有子文件、子文件夹一起处理 |
| 隐藏文件 | 是否处理隐藏/系统文件（默认跳过） |
| 序号 | 在日期后追加 `_001`、`_002`…（可设位数和连接符） |
| 排除扩展名 | 如 `.lnk, .tmp`，命中的文件不处理 |

### 右键菜单
- 自定义菜单显示文字（默认「添加日期前缀」）；
- 可同时注册到「文件夹空白处」右键（对当前文件夹本身生效）；
- 修改文字或选项后需**重新注册**生效；移动程序位置后也需重新注册。

### 撤销
- 每次批量重命名自动记录（保留最近 50 批）；
- 在「撤销」页或结果窗口可整批还原，按相反顺序改回原文件名；
- 原文件名已被占用时会跳过该项并提示。

## 三、常用格式示例

| 想要的效果 | 设置 |
|---|---|
| `20151010 某某文件.pdf` | `%Y%m%d` + 空格 |
| `2015-10-10 某某文件.pdf` | `%Y-%m-%d` |
| `2015_10_10 某某文件.pdf` | `%Y_%m_%d` + `_` |
| `2015年10月10日 某某文件.pdf` | `%Y年%m月%d日` |
| `20151010_1430 某某文件.pdf` | `%Y%m%d` + 时分 |
| `2015-10-10 14-30-05 某某文件.pdf` | `%Y-%m-%d` + 时分秒 |

常用 strftime 代码：`%Y` 年(4位)、`%y` 年(2位)、`%m` 月、`%d` 日、`%H` 时、`%M` 分、`%S` 秒、`%j` 年积日。中文「年月日」可直接输入。

## 四、命令行用法

```bat
RenameTime.exe                  打开设置界面
RenameTime.exe --run 文件...    按设置执行（右键菜单内部调用）
RenameTime.exe --register      注册右键菜单
RenameTime.exe --unregister    注销右键菜单
RenameTime.exe --status        查看注册状态
RenameTime.exe --undo          撤销最近一批重命名
```

把文件/文件夹直接拖到 `RenameTime.exe` 图标上 = 打开预览窗口（先看效果再执行）。

## 五、常见问题

**Q：右键点了没反应/看不到菜单？**
A：先双击 exe 打开设置 →「右键菜单」→【检查注册状态】确认已注册；若移动过程序位置，重新注册一次。程序每次被调用都会写日志 `%APPDATA%\RenameTime\launch.log`，里面能看到系统到底传了哪些参数、出错在哪一步，把该文件发给我即可定位。

**Q：多选了很多文件，会弹很多次窗口吗？**
A：不会。资源管理器对传统右键菜单（注册表静态项）的机制是**每个选中文件各启动一次进程**（且命令里只能用 `%1` 传第一个参数，没有“一次传全部”的写法）。本程序用「队列 + 主控进程」把这些进程自动聚合成**一批**：第一个进程当主控，等约 1 秒收齐其它进程递交的路径后统一执行，只弹一次结果窗口，其余进程静默退出。副产物是每个文件都要启动一次程序，因此**一次选中几十个文件时需要等待几秒**（exe 较大，解压启动有开销），属于正常现象。

**Q：为什么菜单项要放在最上面？**
A：避免和系统自带的「打开」混淆（点错会直接用默认程序打开文件，比如 html 会弹出浏览器）。菜单项已通过 `Position=Top` 固定在右键菜单最顶端。

**Q：反复右键，日期会叠加吗？**
A：默认不会。文件名已包含日期前缀时会跳过；如需用新日期替换旧日期，在「高级选项」选「替换已有日期」。

**Q：改错了怎么办？**
A：结果窗口点【撤销这批重命名】，或在设置界面「撤销」页选择批次还原。

**Q：文件被占用/正在编辑？**
A：重命名会失败并在结果窗口列出该项及原因，其他文件不受影响。

**Q：路径特别长（超过 260 字符）的文件？**
A：程序内部使用 `\\?\` 长路径 API 调用，正常支持。

## 六、文件说明

| 文件 | 说明 |
|---|---|
| `rename_time.py` | 完整源码（Python + wxPython） |
| `RenameTime.exe` | 编译好的主程序（见 [Releases](../../releases)） |
| `test_engine.py` | 重命名引擎自测脚本（26 项断言） |
| `cli_smoke_test.py` | exe 命令行端到端测试（9 项断言） |
| `shellexec_probe.py` | 右键菜单真实调用验证（ShellExecuteW + 多进程聚合，7 项断言） |
| `make_icon.py` | 图标生成脚本 |
| `app_icon.ico` | 程序图标 |

源码运行方式（需 Python 3.8+ 与 wxPython）：

```bat
pip install wxPython
python rename_time.py            :: 设置界面
python rename_time.py --register :: 注册右键菜单（指向 pythonw + 脚本）
```

自行编译 exe（需 `pip install pyinstaller`）：

```bat
python make_icon.py
python -m PyInstaller --onefile --windowed --name RenameTime --icon app_icon.ico rename_time.py
```

配置与撤销历史保存在 `%APPDATA%\RenameTime\`（config.json / history.json / launch.log / rename_time.log）。
