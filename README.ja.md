# RenameTime — Windows 右クリックメニューで「ファイル名に日付を付ける」ツール

[简体中文](README.md) | [English](README.en.md) | **日本語** | [Русский](README.ru.md)

ファイル／フォルダ名を「日付 + 元の名称」に一括で変更します。

```
レポート.pdf（作成日 2015-10-10）  →  20151010 レポート.pdf
```

エクスプローラーでファイル／フォルダを選択し、右クリック → **日付プレフィックスを追加**。
ファイルとフォルダの混在選択も複数選択も、1 バッチとしてまとめて処理されます。

## ダウンロード

**[Releases](../../releases)** からダウンロードしてください
（Windows 10/11 用。Python のインストールは不要）。
初回は一度起動して「コンテキストメニューに登録」をクリックしてください。

| ビルド | ファイル | サイズ | 速度（1 ファイル） | 備考 |
|---|---|---|---|---|
| **推奨** | `RenameTime-fast.zip` | 15 MB | **約 1.6 秒** | 解凍すると `RenameTime.exe` と `_internal` フォルダに展開されます。**フォルダごと移動してください**（exe 単体では動作しません） |
| ポータブル | `RenameTime.exe` | 15 MB | 約 2 秒 | 単一ファイル。どこでも使えるが、起動のたびに自身を解凍するため少し遅い |

> v1.2 以降は zip 版を推奨します。単一ファイル版は起動のたびに依存関係を
> 一時フォルダへ展開するため約 1.5 秒余分にかかります。フォルダ版はそのまま
> 読み込むため起動が大幅に速くなります。機能自体は両者とも同じです。

## v1.2 の新機能：16.8 秒 → 1.6 秒

**リネーム処理自体は常に約 1 ミリ秒でした。** `os.rename` はディレクトリエントリ
だけを書き換えるもので、ファイル内容を読み書きしません。300 MB のファイルでも
0.8 ミリ秒です。時間になっていたのはすべて起動のオーバーヘッドです。

| 段階 | 消費時間 |
|---|---|
| 実際のリネーム | **1 ミリ秒** |
| exe の自己解凍（毎回発生） | 約 1500 ミリ秒 |
| バッチ収束の待ち（ロジックの不具合） | 約 15000 ミリ秒 |

修正点は 3 つ：

1. **バッチ収束の待ちが上限の 15 秒まで空回り**（主因）。旧ロジックは
   「キューが 1 秒静か」でバッチ終了と判定していました。しかし PyInstaller の
   onefile は起動に約 1.5 秒かかり、プロセス開始時刻がばらつくため、最初の
   プロセスが登録して終了した時点では他のプロセスがまだ生成されておらず、
   「バッチ終了」と誤判定され 15 秒の上限まで待っていました。現在の終了条件は
   「キューが 0.35 秒静か」**かつ**「他のプロセスが起動中でない」の両方を満たすことです。
2. **onedir ビルドへの変更**（任意の zip 版）。onefile は起動のたびにランタイム
   全体を約 1.5 秒かけて一時展開します。onedir はそのまま読み込むため約 350 ミリ秒です。
3. **ファイルが黙って変更されない 3 つの競合を修正**（多選時に変更されないことがありました）：
   - キューの取得を「読んでから削除」から**原子的なリネーム**に変更。削除の瞬間に
     届いたパスが一緒に消される事態を防ぎました；
   - リーダープロセスは**処理の終わりまでバッチロックを保持**します。中途でロックを
     解放すると、後から来たプロセスが「フォロワー」になって退出し、そのパスが
     キューに永久に残って誰も処理しません；
   - ロックファイルに書かれた PID が，从来読み取られていませんでした。リーダー
     強制終了されるとロックが 30 秒残り、その間すべてのプロセスが登録するだけで
     実行されません。保持者の生存を確認して、直ちに引き継ぐようにしました。

実測（右クリックからリネーム完了まで、12 回のベンチマーク、**取りこぼしゼロ**）：

| 選択ファイル数 | v1.0 | v1.2 |
|---|---|---|
| 1 | 16.8 秒 | **1.6 秒** |
| 5 | 16.9 秒 | **1.6 秒** |
| 20 | 17.4 秒 | **2.5 秒** |
| 50 | 17.5 秒 | **4.9 秒** |

## ⚠️ 既知の問題

### HTML ファイル：コンテキストメニューの挙動が異常で、現時点では使用不可

`.html` ファイルにコンテキストメニューを使うと、ブラウザーの「تقتحمこのファイルを開きますか？」
というセキュリティ確認ダイアログが表示され、**ファイル名が変更されません**。

| 項目 | 内容 |
|---|---|
| 症状 | リネームされる代わりにブラウザーの確認ダイアログが出る |
| 影響範囲 | `.html`（`.htm` も同の可能性）；その他の拡張子・フォルダーは正常 |
| 現在の状況 | 本プロジェクトの自動テストでは、HTML ファイル（Internet ダウンロード済みマーク `Zone.Identifier` を含むものを含む）は正常にリネームされます。しかし実際のエクスプローラーでは依然として再現するため、**根本原因はまだ特定できておらず、未解決の bug として扱っています** |
| 回避方法 | ① 「実行後に結果ウィンドウを表示」を有効にして、プログラムが呼ばれているか確認する；② 「直接実行」を無効にしてプレビュー確認モードを使う；③ HTML ファイルを `RenameTime.exe` にドラッグする |

再現の際は `%APPDATA%\RenameTime\launch.log` を添付してください（起動のたびに
受け取った引数を記録しています）。

## 1. インストール（30 秒）

1. `RenameTime.exe` をダブルクリック；
2. **「コンテキストメニュー」** タブで **「コンテキストメニューに登録」** をクリック；
3. 完了。エクスプローラーでファイル／フォルダを右クリックするとメニュー項目が表示されます。

> 登録は現在のユーザーのレジストリ（`HKCU\Software\Classes`）に書き込むため、
> **管理者権限は不要**です。アンインストールは「コンテキストメニューから削除」をクリックしてから
> プログラムファイルを削除してください。

## 2. 設定項目

### 基本設定

| 項目 | 説明 |
|---|---|
| 表示言語 | 简体中文 / English / 日本語 / Русский — 画面全体を即時に再構築します |
| 日付の参照元 | 作成日時 / 更新日時 / アクセス日時 |
| 日付形式 | プリセット 8 種、または strftime コードを直接入力 |
| 時刻を含める | なし / 時分（1430）/ 時分秒（14-30-05）、日付と時刻の区切り文字も設定可能 |
| 区切り文字 | 日付と元の名前の間の文字：スペース、`_`、`-`、`.`、なし |
| 位置 | 名前の**前**（接頭辞）または**後**（接尾辞、拡張子の前） |
| 直接実行 | 右クリック後すぐにリネームします。オフにするとプレビューウィンドウが先に出ます |
| 結果ウィンドウを表示 | 実行後に項目ごとの結果ウィンドウを表示（元に戻すボタン付き） |

### 詳細設定

| 項目 | 説明 |
|---|---|
| 日付が既に含まれる場合 | **スキップ**（既定。`20151010 20151010 レポート.pdf` を防止）/ 古い日付を置き換え / さらに追加 |
| 名前が衝突する場合 | 自動的に連番 `(1)`, `(2)`… を付与、またはスキップ |
| 処理対象 | ファイルとフォルダ / ファイルのみ / フォルダのみ |
| 再帰的処理 | フォルダを右クリックしたとき、内部のすべてのファイル・フォルダも対象にする |
| 隠しファイル | 隠しファイル・システムファイルを処理するか（既定はスキップ） |
| 連番 | 日付の後に `_001`、`_002`… を付与（桁数と区切り文字を設定可能） |
| 除外する拡張子 | 例：`.lnk, .tmp` に一致するファイルは対象外 |

### 表示言語（v1.1 新機能）

設定ウィンドウ上部の「表示言語」ドロップダウンで **简体中文 / English / 日本語 / Русский**
を選択できます。

- タブ・ボタン・ツールチップ・エラーメッセージ・プレビュー／結果ウィンドウ、さらに日付形式の
  プリセットに表示されるサンプルファイル名まで、画面全体が即座に再構築されます；
- 選択内容は設定ファイル（`language`）に即時に保存され、次回起動時も維持されます；
- **コンテキストメニューの文字は「コンテキストメニューを登録」を 1 度クリックする必要があります**
  （レジストリに書き込まれた値であり、リアルタイムに読み込まれないため）；
- 初回起動時はシステムの言語環境（`LANG` / `locale`）から推定し、判定できなければ中国語になります。

### コンテキストメニュー

- メニュー表示文字をカスタマイズ可能（**空欄にすると表示言語に追従**）；
- フォルダの空欄部分への登録も選択可能（そのフォルダ自体を対象）；
- 文字やオプションを変更した場合は**再登録**が必要です。プログラムを移動した場合も同様です。

### 元に戻す（v1.1 で強化）

- すべてのバッチ操作を自動記録（直近 50 バッチを保持）；
- 「元に戻す」タブまたは結果ウィンドウから、バッチ全体を逆順で元の名称に戻せます；
- 元のファイル名が既に使われている項目はスキップされ、理由が表示されます；
- **「履歴をすべて消去」**：確認ダイアログ（消去するバッチ数を表示）後、全記録を削除；
- **「リネーム履歴を記録する（元に戻すため）」**：オフにするとその時点から履歴を記録しません
  （元に戻せなくなります）。記録がない場合はボタンは自動的に無効化され、
  チェックボックスの下に現在の状態が表示されます。

## 3. よく使う形式

| 望ましい結果 | 設定 |
|---|---|
| `20151010 レポート.pdf` | `%Y%m%d` + スペース |
| `2015-10-10 レポート.pdf` | `%Y-%m-%d` |
| `2015_10_10 レポート.pdf` | `%Y_%m_%d` + `_` |
| `20151010_1430 レポート.pdf` | `%Y%m%d` + 時分 |
| `2015-10-10 14-30-05 レポート.pdf` | `%Y-%m-%d` + 時分秒 |

よく使う strftime コード：`%Y` 年（4 桁）、`%y` 年（2 桁）、`%m` 月、`%d` 日、`%H` 時、
`%M` 分、`%S` 秒、`%j` 年内通算日。日本語の「年月日/hour」などはそのまま入力できます。

## 4. コマンドライン

```bat
RenameTime.exe                  設定ウィンドウを開く
RenameTime.exe --run ファイル...  現在の設定で実行（コンテキストメニューから呼ばれる）
RenameTime.exe --register       コンテキストメニューに登録
RenameTime.exe --unregister     コンテキストメニューから削除
RenameTime.exe --status         登録状態を表示
RenameTime.exe --undo           直前のバッチを元に戻す
```

ファイル／フォルダを `RenameTime.exe` にドロップするとプレビューウィンドウが開きます。

## 5. よくある質問

**Q: 表示言語を切り替えたのに、コンテキストメニューの文字が古いままです。**
A: メニュー文字はレジストリに保存されておりリアルタイムでは更新されません。「コンテキストメニュー」タブで
「コンテキストメニューに登録」をもう一度クリックしてください。

**Q: 表示言語に関係なく、メニュー文字を固定できますか。**
A: 「メニュー表示文字」欄に直接入力すれば上書きされます。空欄の場合は表示言語に追従します。

**Q: 右クリックしても反応しない／メニューが見えない。**
A: exe を起動 →「コンテキストメニュー」→「登録状態を確認」で確認してください。プログラムを移動した
場合は再登録が必要です。起動のたびに `%APPDATA%\RenameTime\launch.log` に記録しているので、
システムが何を渡してどこで止まったかを確認できます。

**Q: 多数選択するとウィンドウが何度も開く&I。**
A: いいえ。エクスプローラーのレガシー（静的レジストリ）コンテキストメニューの仕組みは、
**選択されたファイルごとに 1 プロセスずつ起動する** もので、コマンドラインも `%1` しか
渡せません。本プログラムは「キュー + リーダープロセス」方式でこれらのプロセスを
**1 バッチ**に統合しています。最初のプロセスがリーダーとなり、約 1 秒間他のプロセスからの
パスを受け取り、まとめて実行して結果ウィンドウを 1 回だけ表示し、残りは静かに終了します。
副作用としてファイルごとにプロセスが起動するため、**数十個選択すると数秒かかります**
（exe の展開と起動のオーバーヘッドによるもので、正常な挙動です）。

**Q: なぜメニュー項目が一番上にあるのですか。**
A: 標準の「開く」項目との取り違えを防ぐためです（誤ってクリックすると既定のプログラムで
ファイルが開いてしまい、HTML ファイルではブラウザーが起動します）。`Position=Top` で
コンテキストメニューの先頭に固定しています。

**Q: 右クリックを繰り返すと日付が二重になりませんか。**
A: 標準ではなりません。ファイル名の先頭に日付が既に含まれる場合はスキップします。
古い日付を新しい日付に置き換えたい場合は「詳細設定」で「日付を置き換え」を選択してください。

**Q: 失敗したらどうすればいいですか。**
A: 結果ウィンドウの「この一括リネームを元に戻す」をクリックするか、設定画面の「元に戻す」タブで
該当のバッチを選びます。

**Q: ファイルが使用中（編集中）です。**
A: その項目だけリネームに失敗し、結果ウィンドウに理由が表示されます。他のファイルには
影響しません。

**Q: 260 文字を超える長いパスです。**
A: 内部で `\\?\` の長パス API を呼び出しているため、そのまま正しく動作します。

```bat
pip install wxPython
python rename_time.py            :: 設定ウィンドウ

```

exe を自分でビルドする場合（`pip install pyinstaller`）：

```bat
python make_icon.py
python -m PyInstaller --onefile --windowed --name RenameTime --icon app_icon.ico rename_time.py
```

```bat
python test_i18n.py

python gui_smoke_test.py     :: wxPython が必要です
python cli_smoke_test.py     :: exe のビルドが必要です
python shellexec_probe.py    :: コンテキストメニューへの登録が必要です
```

設定と元に戻す履歴は `%APPDATA%\RenameTime\` に保存されます
（config.json / history.json / launch.log / rename_time.log）。
